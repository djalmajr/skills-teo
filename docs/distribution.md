# Distribution

## Source

- Public repository: https://github.com/djalmajr/skills-teo
- Install shorthand for the `skills` CLI: `djalmajr/skills-teo`

## Install

```bash
# All skills
bunx skills add djalmajr/skills-teo --skill '*'

# One skill
bunx skills add djalmajr/skills-teo --skill sermao-emilio
bunx skills add djalmajr/skills-teo --skill transcricao

# Explicit agents
bunx skills add djalmajr/skills-teo --agent claude-code --agent opencode --agent codex --skill '*'
```

`npx skills add ...` also works when `bunx` is unavailable.

## Portable contract

Distributed skills live under:

```text
skills/<skill-name>/SKILL.md
skills/<skill-name>/scripts/          # optional
skills/<skill-name>/examples/         # optional
skills/<skill-name>/transcriptions/   # optional
```

Rules:

1. Every skill directory has a `SKILL.md`.
2. Frontmatter `name` matches the directory name.
3. Frontmatter `description` states capability and trigger context.
4. Assets referenced by a skill stay inside that skill directory (or use relative paths from it).
5. Do not hardcode machine paths, personal folders, private notes trees, or host-specific secrets.
6. `skills.json` lists every project-authored skill under source `djalmajr/skills-teo`.

## What is distributed

- `skills/*/SKILL.md` and skill-owned helpers
- Root `README.md`
- `docs/`
- Optional `skills.json` / `package.json`

## What is not distributed as package content

- Locally installed agent skill caches (`.claude/`, `.codex/`, most of `.agents/`)
- Working collections generated by `transcricao` (`raw/`, `artigos/`) unless the user chooses to keep them elsewhere
- Lock files produced by local installs (`skills-lock.json`)

## Update flow

1. Change the skill and any local assets together.
2. Run `npm test` (skill inventory + frontmatter checks).
3. Commit and push to `main`.
4. Consumers refresh with `bunx skills add djalmajr/skills-teo --skill '*'`.

## Checklist before publishing

- [ ] Every directory under `skills/` has `SKILL.md`
- [ ] Every `SKILL.md` starts with YAML frontmatter
- [ ] Frontmatter `name` matches the directory name
- [ ] Frontmatter `description` covers capability + when to use
- [ ] `skills.json` lists every skill directory
- [ ] Human docs under `docs/skills/` stay in sync with skill names
- [ ] Templates/scripts live inside the owning skill
- [ ] No local absolute paths, private repos, tokens, or personal machine names in distributed files
- [ ] Smoke install with `bunx skills add djalmajr/skills-teo ...`
